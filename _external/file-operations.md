# ファイル操作・Undo・中断記録

## 現在の方式

- コピー、移動、名前変更、新規フォルダー、削除は、STAスレッドからWindowsの`IFileOperation`を使用して実行する。
- 名前変更は同じ親フォルダー内の移動として扱う。通常の転送でファイル内容のハッシュは計算しない。
- 操作前に、絶対パス、ローカルNTFS、リンク、ドライブ全体、保護領域、親子関係、同一転送先、空き容量、対象の識別情報を確認する。
- Windows、Program Files、アプリ本体、Liliumの操作記録を含む場所は操作対象にしない。
- 親フォルダーと操作記録を処理中に保持し、別のLiliumによる同時ファイル操作をロックファイルで拒否する。
- Windowsから返る項目別結果、操作全体の結果、中止状態を確認し、完了を確認できない操作を成功扱いしない。

## Undo

- 正常完了した直前1操作だけをUndo対象にする。
- 上書きを含む操作、キャンセル、失敗、結果を確認できない操作はUndo対象にしない。
- 上書き前の項目は先にごみ箱へ移す。フォルダー上書きは統合ではなく全体置換として扱う。
- コピーのUndoは毎回、対象となる操作を固定して確認する。確認後にコピー先が編集・追加されていても、コピー先全体をごみ箱へ移す。
- 移動や削除のUndoでは復元先を上書きしない。別の項目がある場合は拒否し、両方を保持する。
- Undoを自動再実行しない。同じ確認結果を別の操作へ流用しない。

## 操作記録と異常終了

- 操作記録は`%LocalAppData%\Lilium\operations`へJSON形式で保存する。
- 書き込みは一時ファイルへ行い、ディスクへ反映してから確定名へ置き換える。
- Running、Undoing、Failedの未通知記録は、次回起動時または次の操作前にユーザーへ通知する。ファイル操作を自動再開・自動ロールバックしない。
- Cancelledは通常のユーザーキャンセルとして扱う。完了済みの項目はそのまま残る。
- 壊れたJSONや現在扱えない構造は`operations\quarantine`へ自動隔離し、元のバイト列を保持して通知する。隔離処理ではユーザーのファイルを操作しない。
- 壊れた最新記録の後ろにある古い操作を誤ってUndoしないよう、永続的なUndo停止印を先に保存する。
- 隔離に失敗した場合は、閲覧を継続したままファイル操作とUndoを停止する。空き容量、権限、別プロセスによる使用を解消した後に再試行する。
- 未対応の将来形式は変更せず、その形式を扱える版で開くよう案内する。

## UIと終了

- 500ms未満で終わる処理では進捗ダイアログを表示しない。
- 実行中は工程、対象、件数、Windowsの作業量を表示し、キャンセル要求後は安全に停止するまで待つ。
- ファイル操作中にWindowを閉じる操作は拒否する。自動キャンセルや終了予約は行わない。
- 中断・失敗時は元、先、実際の別名結果、ごみ箱へ移した上書き前項目を確認できるよう通知する。

## 検証範囲と制約

- 自動試験では、記録の再読込、部分成功、競合、キャンセル、Undo確認の取り違え防止、壊れたJSONの隔離、隔離失敗時の停止、将来形式の保持を確認している。
- Windowsの操作結果が曖昧な場合は、システムファイル、空フォルダー、代替データストリームを含む操作前後の構成が一致するときだけ完了として調整する。
- 実際の別物理ドライブ、ネットワークドライブ、ディスク満杯、任意時点の強制終了、停電、ファイルシステム破損を網羅する試験ではない。
- ごみ箱を空にした後の復元や、ストレージ自体が書き込み完了を保証しない状況までデータ保全を保証するものではない。
