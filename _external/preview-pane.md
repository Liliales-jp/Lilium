# プレビューエリア

## 配置と設定

「最近の場所」の右に縦線と「プレビュー」トグルを置く。サムネイルの行だけを一覧・境界・プレビューの3列に分ける。とじ方向・並び順・絞り込みの行は従来の幅を維持する。

境界は8 DIP、初期幅480 DIP、プレビューと一覧の最小幅は各320 DIP。両方を確保できないウィンドウでは残り幅を分け、横にはみ出させない。ドラッグまたは境界にフォーカスを置いて左右矢印で幅を変更する。ウィンドウ縮小時の自動調整では希望幅を上書きしない。

`preview_open`・`preview_width`を保存し、ウィンドウごとに独立して操作する。`preview_mode`は全画面用の`viewer_mode`と独立して保存する。とじ方向は既存の`binding`と共有し、所有する一覧にも反映する。

## 対象

- サムネイル一覧で1項目だけ選択されたときに表示する。選択解除・複数選択では、タイトル・画像・案内・下部コントロールをすべて消す。項目をホバーするだけでは変更しない。操作部品へフォーカスを移しても対象を維持する。
- 通常フォルダーは直下の対応画像のみ。隠し・システム項目を除き、現在のファイル並び順を使う。キーワード・評価フィルターはフォルダー内の読書には適用しない。
- ZIP／CBZとアーカイブ内フォルダーは直下の対応画像のみ。非再帰で読み取り専用。
- 画像は、全画面ビューと同じく一覧に表示されている画像列の選択画像から開始する。見開きでは隣の画像も表示する。
- PDFは先頭ページから開始する。非対応ファイル・直下に画像のないフォルダー・読み込み失敗はエリア内の案内にする。自動的に外部アプリを起動したり、ダイアログを開いたりしない。
- 対象変更後200ms待って読み込む。変更前の処理とページ読み込みをキャンセルし、最新の対象だけを表示する。選択解除・複数選択・折り畳み・終了ではすぐに画像とファイル資源を解放する。
- 同じ対象を畳んで開き直す場合はページ・表示モードを復元する。対象変更時は開始位置へ戻す。幅変更では現在のページを保つ。

## 表示・操作

`ReaderView`を全画面とプレビューの両方で使用し、`ViewerSource`・`ViewerPagePlanner`・`ViewerLoadRequests`を共有する。各ビューは自身のソース・PDFセッションを所有する。全画面への引き継ぎは文書の記述・ページ番号・とじ方向を渡し、セッションを共有しない。一枚／二枚表示はプレビューから渡さず、ダブルクリックで開く場合と同じ`viewer_mode`を読み込む。

プレビューの下部コントロールは常時表示する。ページ移動・一枚／二枚表示・とじ方向・全画面で開くに対応する。閉じるコマンドは置かず、ヘッダーの×または上部トグルで畳む。プレビューの幅に合わせて画像を縮小デコードし、サイズ変更が止まってから180ms待って再読み込みする。幅による見開き→一枚の自動切り替えは行わない。

キーボードはプレビューの閲覧面にフォーカスがある場合だけ有効。一覧の予約キー・現在のカスタム割り当てと競合する閲覧キー、すべてのCloseReader入力を無効にする。初期設定の矢印・Home/End・PageUp/PageDown・Enter/Space・数字1/2・ファイル操作キーは閲覧操作にならない。A/D/W/Sは競合がなければ有効。設定のキー一覧に無効理由を表示する。入力欄やボタンの標準操作は奪わない。

マウスはポインター位置で振り分ける。閲覧面のクリック・ホイールは既存のとじ方向と割り当てに従う。コントロール上・境界ドラッグ中・一覧側ダイアログやファイル操作中はページ送りしない。マウス戻るとCloseReaderへの割り当てはプレビュー内で無効。プレビュー内のマウス入力を一覧の履歴移動へ渡さない。プレビュー・境界へのファイルドロップも受け付けない。

## 検証

`dotnet build Lilium.csproj -p:Platform=x64 --no-restore`。

`dotnet run --project Tests/Preview/Preview.Checks.csproj --no-launch-profile`で、標準・カスタム入力の競合、修飾キー、CloseReader、マウス入力範囲、狭いウィンドウの幅、選択解除／新規対象／終了によるリクエスト破棄、見開きの先頭・末尾・横長ページを確認する。

実画面の確認項目：

1. 上部のボタン位置・区切り線と、設定行が縮まないこと。
2. フォルダー・画像・ZIP／CBZ・PDF・非対応・空フォルダーの表示。
3. 選択解除・複数選択で完全に空欄になること。高速な対象変更で古い結果が戻らないこと。
4. 左右のページ配置、クリック・ホイール・ボタンでのページ送り。一覧の選択が変わらないこと。
5. プレビューにフォーカスを置いた時だけ非競合キーが動き、Esc/Backspaceやマウス戻るで閉じたり履歴移動しないこと。
6. 幅変更、狭い幅、折り畳みと再展開、再起動、複数ウィンドウの独立性。
7. 全画面への対象・ページ・とじ方向の引き継ぎと、通常の全画面操作の回帰。一枚／二枚表示は、プレビューと異なる設定にしても全画面用の保存値を使うこと。
8. 読み込み中・PDF描画中に対象変更／選択解除／折り畳み／終了しても例外や表示の逆転がないこと。
9. 表示対象の削除・名前変更・移動後に一覧更新に追従すること。
10. 日本語／英語、100％／150％の表示倍率、画像のEXIF回転、マルチモニターでの全画面表示。

### 起動時クラッシュの回帰確認

フォルダーツリーは`RootNodes`で管理し、展開状態はWinUIが`TreeViewNode`と同期する。項目テンプレートに`IsExpanded`の双方向バインディングを重ねると、スクロールによる行の再利用中にノードが変更され、WinUI内部でアクセス違反が発生していた。この重複を除き、初回の展開とスクロールはそれぞれツリーのレイアウト完了後に行う。

再現したデスクトップを起動先にした状態と、プレビューを開いた状態での深い階層の復元を実機で確認。起動後の自動スクロール・手動スクロール・PDFプレビューの表示が正常に動き、起動直後のクラッシュが起きないことを確認した。
