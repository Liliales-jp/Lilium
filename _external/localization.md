# 日英の表示言語

## 利用者向け仕様

- 言語設定がない場合は、起動時に日本語／Englishの選択画面を表示する。選択を保存してから一覧を開く。選択せず閉じた場合は次回も選択画面を表示する。
- 設定の「表示設定 → 表示言語」で日本語／Englishを選択できる。選択時に保存する。保存できない場合は表示を保存済みの選択へ戻し、理由を表示する。
- 保存しても起動中の言語は変わらない。新しく開く一覧・読書・設定ウィンドウもその起動時の言語を使う。
- 全Liliumウィンドウを閉じて起動し直すと、最後に保存された言語になる。起動中のファイル操作を強制終了する機能は追加していない。
- 未対応の保存値ではWindowsのUI言語に応じた既定値を使用する（日本語なら日本語、それ以外は英語）。未対応値を勝手に書き換えず、設定で選び直せる。
- 初回の選択画面は両言語を併記する。言語名は常に「日本語」「English」。
- ヘルプは実行中の言語に対応したファイルを開く。

## 実装と翻訳の追加方法

- `Strings/ja.json` と `Strings/en.json` が文言一覧。361項目（キー設定追加後）。両方をアセンブリに埋め込み、配布時の翻訳ファイル不足を避ける。編集した翻訳を反映するには再ビルドする。
- キーは固定の識別子。既存キーを並べ替えや削除に合わせて振り直さない。新しい文言は役割が分かる新規キーを両言語へ追加する。
- C#は `L10n.Get(key)`、可変値は `L10n.Format(key, values...)` を使用する。`{0}` 等の番号と `:X8` 等の書式は両言語で揃える。語順に合わせて番号の位置は変えられる。
- XAMLは `Ui_` で始まるキーを `StaticResource` で参照する。起動時、最初の一覧を生成する前にApplication.Resourcesへ登録する。
- `L10n` は読み取り専用の文言辞書を保持する。言語の初期化は起動処理だけで行い、設定保存ハンドラーからは呼ばない。
- SQLiteの既存settingsテーブルに `language=ja/en` を保存する。スキーマ変更・データ移行はない。
- Windows App SDKの標準コントロールにも起動時に言語を指定する。Windowsのごみ箱やエクスプローラー、OSが生成する例外文はWindows側の言語で表示される場合がある。
- ファイル名・ユーザーのパス・保存済みの過去のエラー記録は翻訳し直さない。診断用の内部ログは英語のままのものがある。

## 確認

自動確認は作業フォルダーの `work/localization/tests/LocalizationChecks.csproj`。キー集合、重複、翻訳漏れ、埋め込みリソース、書式・引数、C#／XAML参照、SQLite保存、再起動までの表示維持、逆方向への変更、保存失敗時の値保持を確認する。

既存の単独テストプロジェクトから現在のソースをリンクして実行する場合、`work/localization/Localization.targets` を `CustomAfterMicrosoftCommonTargets` に指定すると、L10nと埋め込み辞書を読み込める。

実機で未確認の項目：

1. 言語未選択で起動して、各言語を選ぶ。選択画面だけ閉じた場合はアプリが終了する。
2. 日本語→英語を保存しても表示は日本語のまま。設定を閉じて開き直すとEnglishが選択済みで再起動案内が出る。
3. 全ウィンドウを閉じて起動し直すと英語になる。英語→日本語でも同様。
4. 言語変更後、再起動前に別の一覧・読書ウィンドウを開いても、同じ起動中の言語を保つ。
5. 一覧、右クリック、設定、進捗、削除確認、エラー、読書画面、ヘルプを両言語で確認する。Windowsの表示倍率100％／150％で、文字切れと折り返しを確認する。
6. キャッシュ容量は従来どおりスライダーと適用ボタン、最後の一覧を閉じると設定も閉じることを確認する。
